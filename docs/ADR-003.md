# ADR 003 — Voltar o código não desfaz a mudança dos dados

Estado: aceita no escopo deste exercício local. Data: 09/11/2026.

## Contexto
Uma aplicação antiga espera `legacy_name`; a nova lê `display_name`. Uma alteração destrutiva pode tornar o banco incompatível com o binário anterior. Snapshot anterior pode omitir escritas válidas realizadas depois dele.

## Decisão demonstrada
Expandir antes de contrair. Durante a janela de compatibilidade, preencher a nova coluna e escrever em ambas, na mesma transação local. Bloquear a troca quando há divergência ou campo novo ausente. Manter a leitura antiga disponível durante a janela. Só contrair com a aplicação nova ativa e reconciliação consistente.

Depois da contração, bloquear a aplicação antiga. Para uma mudança real, aprovar previamente plano de correção para frente, backup restaurável, captura das escritas posteriores, reconciliação dos efeitos externos e responsáveis pela decisão. Um backup não é confirmação de recuperação.

## Evidência
Seis testes de compatibilidade, escrita dupla, divergência, contração, snapshot e precondição. `python change_lab.py demo` mostra dois pedidos após rollback de aplicação, um pedido ausente no snapshot e bloqueio da versão antiga após contração.

## Limites
Dado fictício, SQLite local, uma única conexão para mudança. Sem migração on-line distribuída, persistência da flag entre processos, restauração executada, failover, efeitos externos, RTO ou RPO medidos. Não demonstra uma entrega de cliente nem revisão independente. A remoção é feita apenas na pasta temporária do próprio exemplo.
